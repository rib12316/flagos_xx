## 判读

- **假设证实**：`_FUSED_GEMM_MIN_M=256` 是按 (256,256) 大 tile 败绩设的偏保守门——
  decode M=64/128 用小 BM tile 全面赢链，最大 1.62×（o_proj）。
- M=64 与 M=128 最优配置分叉（gate_up：BM64 vs BM128）→ 表按 **(M,K,N) 精确键**。
- lm_head M=64 不过闸（1.106×）→ 该点保持 cuBLAS 链；M=128 过闸（1.165×）随 P1
  ckpt v2 上线自动生效（bf16 lm_head 的 N 不在表内，永不路由）。
- BK=128 在 o/down/qkv-M64 显著占优（K 循环迭代减半），与 prefill 档 BK=64 不同。
- 整链基线带宽：gate_up M=64 412GB/s、lm_head M=64 453GB/s、M=128 374GB/s——
  decode 档确在权重读带宽域（远低于 829GB/s 读流天花板，链式 int32 [M,N] 往返 +
  三 kernel 依赖链是差距来源，融合单 kernel 吃掉这部分）。
- serve 兑现路径：decode 在 FULL_DECODE_ONLY cudagraph 内 → 纯 GPU 时间收益直接进
  ITL；每层 4 线性 M=64 档合计 65.2+25.2+24.9+48.6=163.9µs → 56.2+17.4+15.9+31.1=
  120.6µs，**每层省 43.3µs**（×42 层 ≈ 1.82ms/forward 的 GPU 时间）。
